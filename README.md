# YouTube 学习资料下载器

> 仅用于个人学习。请只下载自己有权访问的内容，并遵守版权规则和 YouTube 服务条款。

这是一个面向课程和播放列表整理的本地下载工具。前端使用 React，后端使用
Express + yt-dlp，下载记录保存在 SQLite，并提供可直接安装使用的 Windows
Electron 桌面版。

## 已实现

- 视频、播放列表、频道和搜索解析
- 单个或批量加入下载队列
- 连续解析不同播放列表时自动隔离选择与格式状态，避免旧列表索引串入新列表
- 真实下载进度、速度、已下载大小和 ETA，并区分视频轨、音频轨、合并与后处理阶段
- 全局后台同步下载状态，离开队列页后仍会提示完成或失败，并显示待处理任务数量
- Windows 任务栏显示后台下载进度；窗口不在前台时用系统通知报告完成或失败
- 关闭主窗口时隐藏到系统托盘并继续下载；托盘右键“退出应用”时保留活动任务确认
- 网络错误自动退避重试、磁盘空间预检和可行动的失败提示
- 精确识别浏览器 Cookie 复制、解密、缺失和文件格式故障
- YouTube 连接诊断与 HTTP/HTTPS/SOCKS 代理设置
- 推荐画质预设与单视频实际格式轨道选择；4K/8K 等选项只从当前视频真实格式生成
- MP4/WebM 合并、MP3/M4A 音频提取
- 音频与字幕组合防呆：MP3/M4A 禁止嵌入字幕，并自动保留为外挂 SRT
- 字幕轨道选择、预览、单独下载与随视频处理
- 应用专用 Chrome 登录、Chrome Cookie 快照、浏览器直读或 Cookie 文件导入，并可就地验证
- 专用登录与 Cookie 配置跨重启恢复，不要求关闭日常 Chrome
- 字幕预览与单独下载
- SQLite 队列恢复和下载历史
- 任务、历史与普通设置可导出为本地备份并经校验安全恢复；Cookie 和媒体文件默认排除
- 活动任务持久化保护：历史删除不会绕过队列状态或误删未完成任务
- 已完成文件可直接打开或在 Windows 文件夹中定位
- 重复任务/已有文件整批保护，确认后自动以 `(2)` 等序号安全另存
- 下载目录、并发数和命名规则持久化设置
- PWA、亮色/暗色/跟随系统主题
- Windows 桌面启动、内置工具自检和安装包配置
- 桌面版内置 Deno，并显式提供给 yt-dlp 的 YouTube EJS 挑战解析
- 首次使用准备向导、一键脱敏诊断报告和 yt-dlp 官方 Nightly 安全更新

## 桌面版第一次使用

普通用户直接运行 `release` 目录中的安装版或便携版，无需安装 Node.js、
Python、yt-dlp、Deno 或 ffmpeg。首次打开会显示“首次使用准备”向导：

1. 确认下载目录、yt-dlp、Deno 和 ffmpeg 均为可用状态；
2. 点击“测试 YouTube 连接”；该操作只解析官方测试视频，不下载媒体；
3. Cookie 是按需项，普通公开视频可以先不配置；
4. 如果 YouTube 提示人机验证，进入“设置 → Cookie 配置”，点击“打开专用登录窗口”；
   在新打开的独立 Chrome 中登录 YouTube，关闭这个专用窗口，再回到应用点击“完成授权”。日常
   Chrome 可以保持打开，后续解析和下载也不会读取它的 Cookie 数据库；
5. 点击“测试当前配置”，确认当前组合能正常解析官方测试视频；
6. 如果解析突然失效，可在“设置 → yt-dlp 更新”更新到官方 Nightly；
7. 如果网络超时或无法连接，可在“设置 → 网络与连接测试”配置代理并运行诊断。

成功标志：向导中的本机必需项目与 YouTube 连接均显示绿色勾，随后可以在首页粘贴链接并解析。
解析期间首页会显示明确的等待提示；即使临时切换到设置或下载队列，已粘贴的链接和解析状态也会保留。
解析成功或失败后按钮会恢复可用，失败时会显示原因和对应的处理入口。

粘贴的 Cookie 必须以明文文件提供给 yt-dlp，但应用会将文件保存在本机应用数据目录，
使用仅当前系统账号可读的文件权限，并且不会在 API 响应或日志中打印 Cookie 内容。
Chrome 用户建议使用应用专用登录：可见登录阶段不启用远程调试；关闭专用窗口后，应用才会用
仅监听本机的临时调试端口读取独立用户数据目录，只导出 YouTube 域名 Cookie 到本机受保护文件，
不读取日常 Chrome 配置。登录状态可能失效时，
重新打开专用窗口登录即可。旧版快照、浏览器直读和 Netscape Cookie 文件方式折叠在“高级
兼容方式”中，其中前两种仍可能要求关闭浏览器。升级时，旧版直读配置会自动停用并提示迁移，
避免每次解析都重复要求关闭 Chrome。
若 Cookie 配置测试仍失败，应用会区分数据库被占用、Windows 解密失败、数据库缺失和文件
格式错误，并给出对应修复入口。仍失败时可改用 Firefox，或重新登录 YouTube 后导出最新文件。
验证过程只解析官方测试视频，不下载媒体。

关闭主窗口不会结束应用，而是隐藏到 Windows 右下角托盘，下载任务继续运行。单击托盘图标
或右键选择“打开主界面”可恢复窗口；右键选择“退出应用”才会真正退出。若仍有活动任务，
退出前会明确确认，避免误停下载。

## 下载进度与选择记忆

下载队列同时读取 yt-dlp 的标准输出和错误输出。文件大小已知时显示真实百分比、速度、
已下载大小、总大小和 ETA；大小未知时显示“进度未知”及实际已下载大小和速度，不再用假的
0% 冒充进度。音视频分轨下载会依次显示“正在下载视频”“正在下载音频”，随后显示合并或
后处理阶段；任务只有在 yt-dlp/ffmpeg 进程成功结束后才标记完成。

首页会跨页面和应用重启记住 MP4/WebM、画质、字幕模式、字幕语言和自动字幕选择。同一个视频
重新解析时保留其实际格式 ID；不同视频按视频 ID 隔离，旧 ID 不在最新格式列表中时会明确
提示并要求确认。画质下拉框由解析结果动态生成：源视频和所选容器有 8K/4K 时才显示对应选项，
最高只有 1080p 时不会显示虚假的 4K，也不会静默把 WebM 或最高画质改回 MP4/720p。

## 下载失败时生成诊断报告

进入“设置 → 诊断与日志”，点击“生成脱敏诊断报告…”，再在 Windows“另存为”窗口中
选择保存位置。应用只会在用户确认后写入本地文本文件，不会自动上传。

报告包含应用版本、系统与内置工具状态、非敏感设置摘要和最近的后端日志尾部；默认遮蔽
Cookie、认证信息、代理凭据、URL 查询参数、下载目录和完整用户目录。脱敏属于防御措施，
把报告发给他人前仍建议自己打开浏览一遍。需要深度排查时，原始 `backend.log` 仍可从
同一区域的“打开原始日志目录”进入，但原始日志不应直接公开分享。

## 本地数据备份与恢复

进入“设置 → 本地数据备份”可导出一个 JSON 备份文件。备份包含任务、历史、下载目录、
命名规则、并发数、重试次数和不含登录凭据的代理地址；不包含 Cookie 内容，也不会复制
已经下载的视频、音频或字幕文件。备份中仍含视频标题和本机路径，不建议随意公开。

恢复时应用会先校验文件格式和所有任务字段，再显示原生确认框。正在运行或等待的任务必须
先暂停或取消；确认恢复后，当前任务、历史和普通设置会被替换，应用自动重启。备份中原本
处于运行状态的任务会恢复为“已暂停”；可重试任务的旧路径若超出当前下载目录，会迁移到
“已恢复任务”子目录，避免备份文件把下载写到任意位置。

## 下载完成后

下载队列和历史页会为已完成任务显示“打开”和“文件夹”按钮。“打开”使用
Windows 默认程序播放或查看文件；“文件夹”会在文件资源管理器中定位该文件。
如果文件已被移动或删除，应用会明确提示，而不会静默失败。

失败记录会显示可执行的下一步建议；即使重启应用，也可在历史页点击“重新下载”，
继续使用原任务的格式、目标位置和已保留分片。暂停与失败会保留断点，取消任务则会在
下载进程退出后只清理该任务的隔离分片和目标文件。

如果刚点击暂停或取消就立刻移除，应用会等待下载进程真正退出，避免 Windows 文件句柄
尚未释放时留下分片。删除或清空历史后，队列中的对应终态记录也会同步消失。

再次提交会写入同一路径的任务时，应用默认不创建整批任务，避免播放列表只成功
一半或覆盖旧文件。确认继续后，仅冲突项会自动改名为 `文件名 (2).扩展名`、
`文件名 (3).扩展名`，已有文件保持不变。

## 环境要求

- Node.js 22.12 或更高版本
- 开发环境可使用系统 `yt-dlp` / `deno` / `ffmpeg`
- 桌面发布需要把 `yt-dlp.exe`、`deno.exe`、`ffmpeg.exe`、`ffprobe.exe` 放入
  `resources/bin`

## 第一次运行

以下命令会从 npm 下载依赖并在项目目录创建 `node_modules`。如果网络使用代理，
需先保证 npm 能联网。

```powershell
# 1. 安装后端和桌面依赖
npm install

# 2. 安装前端依赖
npm --prefix client install

# 3. 启动后端
npm run dev

# 4. 另开一个 PowerShell 窗口，启动前端
npm --prefix client run dev
```

成功标志：

- 后端窗口显示 `后端已启动: http://localhost:3000`
- 浏览器打开 `http://localhost:5173`
- 设置页的运行环境区域能显示 `yt-dlp`、`Deno` 与 `ffmpeg` 状态

## 测试说明

`npm test` 会自动运行 `tests` 目录中的全部单元测试和本地 HTTP 集成测试。
这些测试使用临时目录和可控的模拟下载器，不访问 YouTube，也不会写入现有下载记录。

维护者还可以主动运行一次真实 YouTube 冒烟测试：

```powershell
$env:YLD_E2E_LIVE = '1'
npm run test:e2e
Remove-Item Env:YLD_E2E_LIVE
```

该命令只使用 yt-dlp 官方测试视频，并使用 `resources/bin` 内的 yt-dlp、Deno 与 ffmpeg，
在系统临时目录中完成解析、下载、取消、历史
记录与重启恢复检查。成功标志是输出 `"ok": true`；如果返回 `RATE_LIMITED`，说明
当前网络被 YouTube 要求人机验证，应先在桌面版“设置 → Cookie 配置”中完成配置。
测试脚本不会自动读取浏览器 Cookie。

如果当前网络被 YouTube 要求人机验证，并且设备所有者明确允许测试读取已登录浏览器的
Cookie，可额外设置 `YLD_E2E_COOKIE_BROWSER` 为 `chrome`、`edge`、`firefox` 或
`brave` 后重跑。该选项不会导出或打印 Cookie 内容；未经授权不要启用。

需要验收 Chrome 快照时，必须先完全关闭 Chrome，并在设备所有者明确授权后改用：

```powershell
$env:YLD_E2E_COOKIE_SNAPSHOT = 'chrome'
$env:YLD_E2E_LIVE = '1'
npm run test:e2e
Remove-Item Env:YLD_E2E_COOKIE_SNAPSHOT
Remove-Item Env:YLD_E2E_LIVE
```

该模式在隔离的系统临时目录导入快照，确认后续解析和小体积下载使用 `--cookies` 快照文件，
结束后自动删除整个临时目录；不会修改安装版正式数据，也不会输出 Cookie 内容。

安装包验收时可额外设置 `YLD_E2E_PACKAGE_ROOT` 为刚安装完成的应用目录。脚本会直接
使用该目录中的 Electron 运行时、生产后端、yt-dlp、Deno 和 ffmpeg，不会退回源码环境：

```powershell
$env:YLD_E2E_PACKAGE_ROOT = 'C:\Path\To\Installed App'
$env:YLD_E2E_LIVE = '1'
npm run test:e2e
Remove-Item Env:YLD_E2E_PACKAGE_ROOT
Remove-Item Env:YLD_E2E_LIVE
```

在 YouTube 不可访问时，可用完全离线的 UI 验收数据检查格式和字幕界面：

```powershell
npm run build
$env:YLD_UI_FIXTURE = '1'
npm run ui:fixture
```

成功标志：终端显示 `UI fixture ready`，打开对应本地地址后，输入任意内容并点击
“解析”，即可看到带实际格式和字幕轨道的测试视频。该模式不会进入桌面安装包。

## 配置

桌面版可在“设置 → 下载设置”中选择下载目录、并发数、自动重试次数和命名规则，保存后立即用于
新加入的任务并写入 SQLite。降低并发数不会强行中断已经运行的下载。

同一处设置还提供“温和下载模式”（默认开启）。开启后每个下载任务会限制到配置的 MB/s
字节速率、使用单个并发分片，并在任务之间等待冷却时间；解析请求也会放慢请求节奏。温和模式
有效并发固定为 1，但仍保留“同时下载数量”设置，关闭模式后会恢复该设置。播放列表或频道批量
提交时受“单次批量上限”限制，单视频提交不受此限制。该模式只能降低请求频率，**不保证不被
YouTube 限流**；如果触发限流或 Cookie 错误，当前任务失败，后续任务会暂停，需要处理设置后
逐个恢复。第一阶段不包含代理轮换、浏览器伪装或其他反检测能力。

“设置 → 网络与连接测试”可保存 yt-dlp 专用代理，并用官方测试视频做只解析、不下载的
连接诊断。支持 `http`、`https`、`socks5` 和 `socks5h`；留空表示直连。为避免登录凭据
以明文保存在 SQLite 中，应用拒绝包含账号或密码的代理地址。

开发环境也可复制 `.env.example` 为 `.env` 后按需修改默认值。该示例不包含 Cookie
或其他登录凭据。桌面版首次启动会
使用系统下载目录；如果已保存的目录暂时不可用（例如移动硬盘未连接），会安全
回退到默认目录，不影响应用启动。
